# 7. 流程-特殊版面與丟棄規則

不是每一行都該變成文字。這一章收兩類：**非水平的版面**（弧形、傾斜、直排）需要特殊幾何；而**轉成文字必然失真的行**（插圖內的小字、線稿圖示、上下標公式）則一律留原圖。

⚙️ **動到丟棄規則、浮水印，或弧形／直排／旋轉路徑之前請先讀完這一章。** 實作上的落點（模組、函式名）見 §12。

> 這些條目原本住在 `CLAUDE.md` 的「架構」章，2026-08-23 搬進規格書；2026-08-24 改寫成技術中立，門檻、實測數據與反例一字未動。

## 7.1 非水平的版面

- **弧形文字**（第 3 頁緞帶橫幅）：弧度只能從**救援片段中心**擬合。⚠️ **純影像逐欄追蹤法已嘗試並放棄** — 平行的兩條弧線框深度交疊、互相污染、連符號都會判反。高分的鄰行用「夥伴傳播」繼承曲率（同半徑 → 弧深隨寬度平方縮放）。

  ⚠️ **輸出端用 PowerPoint 內建的彎曲文字效果（textArchUp/Down）也已嘗試並放棄**：其下沉量 ≈ 0.13×框高（實測校準），但字級／路徑縮放行為不透明，長文字會繞圈重疊 — 改用 **3–6 段切線文字方塊**沿拋物線排列（局部切線角 = atan(2·弧深·t/半寬)），色塊用 12 條沿弧條帶（縱向邊距 0.3 字高吸收拋物線 vs 圓弧的側翼偏差）。段落切割用 em 寬度加權並貼齊空格。

  ⚠️ **拋物線錨點不能用 `bbox`**（救援片段會把框灌高：中段錨點實測低了 39px、弧深 172px vs 實際 ~97px）— 改用渲染圖在中心與 ±0.65 翼側量「文字色字墨 run」重新錨定，每個探測點取離預測最近的 run（同一緞帶有兩行弧線、視窗會同時看到兩條字墨帶）。

  條帶高 1.5×字高（2.2× 會把上緣的柔和漸層蓋成一條硬邊 — 使用者回報過）；垂直範圍再夾進緞帶本體（只縮不放）：字墨中斷的橋接只允許在距切線中心 ±0.9 字高內，區外只容 10px — 否則會跨過「邊緣帶＋白縫」橋接到同色的虛線、夾製整個失效；並沿條帶取 3 個樣本欄、在切線座標系取極值，旋轉後的角落才不會凸出緞帶（曾在翼側產生凸塊）。相鄰條帶的角差會在底部張開楔形縫，條帶寬度要加 `strip_h × Δslope` 的重疊量補縫。

- **直排 CJK 文字**（使用者指示 2026-06-13）：偵測框內字垂直堆疊的純 CJK（p7 象限圖 y 軸標籤「純寫作」「技術開發」）——框高窄、≥2 個純 CJK 字、且每字格近正方（框高/字數 ÷ 框寬 ∈ [0.55, 1.7]）。字級取**字欄寬**（每字與欄同寬）而非堆疊高、蓋板涵蓋整框、輸出用東亞直排文字框（置中、無 leading 內距）。原本當水平行處理 → 字級量太小、文字水平排不蓋住直排點陣（使用者回報）。全文僅這兩個標籤觸發、零誤判。

- **傾斜需要基線：單一字形的角度一律丟棄**（使用者回報 2026-08-17）：文字的方向是由「多個字沿基線排列」定義的，**只有一個字就沒有基線**，偵測器的 min-area 四邊形會改鎖到該字自己的筆畫方向或任意對角線。p15 圓形步驟徽章裡的白色「1」因此回了 **26.31° 的旋轉四邊形、分數卻高達 0.956**（不是低分救援路徑），渲染出來是一撇斜的筆畫、看起來就是斜體「7」。

  兩份 deck 共 29 頁全掃：**合法的傾斜行全部 ≥2 字且去斜後明顯狹長**（p6 三個「Step」，角度 5.1–5.9°、w/h 1.83–1.90），**而每一個單字元傾斜都是假的**（'1' 26.31° w/h 0.96、'←' −6°、'と' −26.9°）。閘門放在兩處共用：偵測器四邊形的角度計算，以及旋轉救援的角度採用點 —— 救援的**文字照樣採用**，只丟掉沒有基線支撐的角度。

  ⚠️ **不可改用「去斜後 w/h 狹長」當閘門**：兩字的斜置籌片（p8「98」）w/h 只有 ~1.1，會被一起殺掉。丟掉角度後該行走一般路徑（色塊＋文字框，形狀數 +1），點陣仍被完整蓋住。

- **傾斜文字，兩種情況**：
  1. **偵測器回傳「旋轉四邊形」**（例如第 5 頁 26° 的金字塔色帶）：角度／中心／轉正尺寸存進 `Line`；取樣顏色與墨水時用**轉正後的貼片**（⚠️ 若改用軸對齊外接框取樣會混入周圍顏色 — 那個 bug 曾產生蒼白的蓋板）；輸出旋轉形狀（兩者皆順時針為正，PowerPoint 以形狀中心旋轉）。
  2. **偵測器把傾斜文字合併成「軸對齊」框**（第 3 頁的弧形緞帶）：該行分數會 < 0.75 並觸發旋轉救援 — 將外擴裁切以 ±3/6/9° 重新 OCR，只保留「自身高度帶跨過裁切中心」的片段（否則鄰行會混入），在「長度不超過原文 2 倍」的前提下取最長、分數最高的組合。⚠️ **PCA 與投影剖面去斜都在這種雜訊裁切上失敗過**；暴力法勝出。當四邊形已帶角度（情況 1）時跳過救援。救援成功時同時重建旋轉矩形（用 `p_in = c_in + R(+θ)(p_out − c_out)` 映射回原圖，已數值驗證），輸出形狀同樣旋轉 — ⚠️ **高度要用片段高度的中位數，不能用四邊形聯集**（弧形片段會把聯集灌爆：243px vs 實際 ~80px）。

## 7.2 浮水印

- **浮水印品名是清單、不是單一字串**（使用者回報 2026-08-17）：產品會改名而**已匯出的舊 PDF 仍帶舊標記**，所以字尾比對必須同時收 `notebooklm`（2026 年中以前）與 `gemininotebook`（之後；去空格後比對，原文是「Gemini Notebook」），並以 casefold 比對。新標記整份 12 頁 OCR 全讀成乾淨的 'Gemini Notebook'（14 字、去空格），舊上限 16 字看似夠、但**是品名字尾比對那一關擋下的** —— 症狀就是整份浮水印一個都沒清掉、變成可編輯文字。

  ⚠️ **位置閘門補不了這一刀**：底右角（y>0.85H、x1>0.65W）同樣會命中橫跨整頁底部的引言帶（新 deck p3 的紅底標語 y0=1976、x1=3233 兩條都過），只有品名能區分。前綴雜字上限改成「扣掉標記後 ≤6 字」（原本是總長 16 減 10，等價）：OCR 有時把 logo 與淡淡的頁碼戳記一起併讀（舊 deck p1 讀成「P92F2NotebookLM」）。

- **浮水印遮擋範圍要量、不能用框高的倍數猜**（2026-08-16 審查）：遮擋盒的上下界曾是 `y0−0.05h` / `y1+0.12h`，理由是「在這張渲染圖上量到膠囊頂在 y0+0.16h、淡色膠囊底在 y1+0.10h」——**下緣只剩 0.02h 餘裕**，框高 25–50px 時是 0.5–1px，小於膠囊邊緣本身 1–2px 的反鋸齒暈。

  這正好違反本書第二重要的不變量「偵測框的留白不一致」：單一渲染圖校準出來的倍數對下一份 PDF 沒有保證，而且 **logo 圖示比文字帶高、又可能整個落在 OCR 框外**（⚠️ 這是當時 `SOURCE.pdf` 的觀察；2026-08-17 複驗的新舊兩份 deck 都是 logo **在框內**、距框左 3–5px —— 這正是「框預測不了浮水印」的另一面，**兩種都要能處理**），框的任何尺寸都預測不了它。

  改成在遮擋盒自己的欄帶內掃描列墨、再加 **2px 邊距**，最後**鉗進 [tight, wide]**：不得比使用者調過的緊盒更緊（`y0−0.05h`／`y1+0.12h`，使用者 2026-06-15「剛好遮住即可」），也不得超過改動前的 0.35h／0.40h —— 掃描失敗就退回已知可用的行為，永遠不會吃到投影片內容。沒有渲染圖時退回緊盒。

- **掃描要「從浮水印往外走、遇空白就停」，不是取視窗內最外側的墨**（2026-08-17）：取極值的版本會把**碰巧靠近角落的頁面元素**一起吞進來，再被鉗制放大成 wide 盒塗掉它（新 deck p8 的灰色卡片離浮水印 14 列、p1 的頁框底線離 8 列，舊 deck p5 的格線離 20 列 —— 全被塗）。改成從文字帶取起點（框中央 60% 內的有墨列，框緣正是外來墨滲入處）向外走，連續 `gap` 列全空白就停；**浮水印自己的零件（logo／字／膠囊）之間沒有任何空白列**，這個間隙就是判別。

  三個 gap 不同（皆下限 4px）：垂直 0.15h、**左 0.35h**（要跨過 logo 與品名之間的詞距，萬一 logo 落在框外）、**右 0.10h**（字尾之後不再有浮水印零件，而頁框右線只離 8px）。

  - ⚠️ **列的有墨門檻是 0.05 不是 0.01**：貫穿整條視窗的**頁框直線只佔 1–2% 欄**，卻讓每一列都算「有墨」→ 掃描永遠走不到頭、退回 wide，而 wide 恰好蓋掉頁框底線（新 deck p1 實測底線 y=2120–2125、wide 下界 2126）。浮水印自身最稀疏的列（logo 尖端）仍佔 10–11%，兩者中間切 5%。
  - **水平也要量，且允許往框內縮 0.3h**：`x0−1.8h`／`x1+0.3h` 是為「logo 在框外」猜的倍數，但兩份 deck 實測 **logo 都在框內**（新 deck 距框左 3px、舊 deck 5px），左延 68–90px 只會塗掉旁邊的頁面內容（新 deck p12 的水平分隔線被截斷一截）。⚠️ **右側更要縮**：OCR 框右緣本身就壓在頁框直線上（框 x1=3798、線 3798–3803），不准內縮就一定塗掉線。量出來的邊界鉗進 `[x0−1.8h, x0+0.3h]`／`[x1−0.3h, x1+0.3h]`，掃描失敗（紙紋背景讓整片連通：舊 deck p1/p12）照樣退回原本的 wide。

  驗證：新 deck 12/12、舊 deck（`Transformer_演進地圖_NotebookLM簡報.pdf`）12/12 全數偵測且盒外 4px 環帶無殘墨（唯二報墨的是舊 deck 兩張紙紋頁與新 deck p8 的灰卡，皆為**正確避開**的頁面內容）；PowerPoint COM 匯出目視 p1/p8/p12：浮水印消失、頁框線與灰卡完整。

## 7.3 轉不好就別轉

- **無法忠實還原的行保留原圖**（浮水印過濾後、在「太小／模糊」那道之前跑、與 `--keep-tiny-text` 無關；使用者指示 2026-06-13）：以下視覺內容轉成可編輯文字必然失真，整行丟掉露出點陣。
  - **(a) 線稿圖示被讀成單字母**（p4 交叉箭頭 shuffle 圖示 → 40pt 的「X」）：單一拉丁字母、≥28pt、且該列無其他真文字（垂直不重疊任何行）即判圖示 — 真的單字母內容（X² 變數）一定有同列鄰字、不會在標題級孤立。實心圖示偵測（見 §3）只抓「填充＋描邊」雙色圖示，**線稿單色圖示靠這條**。
  - **(b) markup 示範的刪除線**（p13 `==螢光==` 的 光 上疊紅 ✗ 讀成 `==螢×==`）：含 `==` 且含 `×` → 刪除線疊字無法還原（p6 純 `==螢光筆==` 無 × 不丟，照常轉字）。
  - **(c) 上下標公式**（p12 H₂O X² 被辨識模型壓平成 `H2OX2`）：word box 是詞層級、拿不到每字基線，只能靠點陣 — 短純英數行（3–8 字、含數字含字母、無 CJK）切欄量各字墨重心，散佈 >0.25 行高即判上下標。
  - **(d) 線稿圖示被讀成單一 CJK 字**（p14 CPU/IC 晶片圖示讀成「尚」）：把該字以 YaHei 渲染、與框內字墨各自緊裁縮放到 64×64 比 IoU——真字會與自身渲染重疊（0.35–0.65），圖示不會（尚 IoU 0.20）。⚠️ **保守取 AND**：分數 <0.92 **且** IoU <0.30 才丟（正確讀出的單字分數高或 IoU 高、永不誤丟）。全文僅一個單 CJK 字行（就是這個圖示），其餘真字都是詞／句的一部分。
  - **(e) 未偵測到旋轉的圖表軸標籤**（p11 Y 軸「修復成本 (指數型攀升)」）：偵測器把 90° 旋轉的軸標籤回成角度 0 的軸對齊框、框**高遠大於寬**（121×819，h/w=6.8），被當水平文字量成 8pt 小字、既不蓋住也不對齊側躺的點陣。此處旋轉／字級都不可靠，使用者裁定（2026-06-14）「這個字可以不轉換」→ 整行丟掉留原圖。判別：`h > 2.5×w` 且非直排（直排堆疊 CJK 由東亞直排文字框正常處理、保留）、非旋轉／非弧形（偵測到的旋轉照樣旋轉渲染、保留）、含 CJK。水平行 w≫h 永不觸發。

- **太小／模糊的行不轉文字、保留原圖**（浮水印過濾後、字級調和前跑；`--keep-tiny-text` 可關；使用者指示 2026-06-12）：插圖內文（p11 命盤／流程圖／終端機 46 行亂碼、p10 書脊、p7 渦輪機標籤）轉出來是錯字蓋板、比留原圖更糟。

  **門檻**：≤9pt 預設丟、乾淨小字放行（純 CJK 2–4 字且分數 ≥0.85 → p5 金字塔籌片 0.89–0.93；其他 ≥0.94 → p9 時間戳）；≤14pt 且 <0.72 丟（p3 `<小>` 0.57、p9 斜置籌片 商業策略 0.69）；**純拉丁行**（無 CJK）分數 <0.75 丟，不限長度也不限字級（p14 `di` 0.53、p10 `Al` 28pt 0.72、rlbp p8 的上下標公式被讀成 `DtsaDtse` 0.63 與 `OtSat$Set` 0.58、gptbp p7 的 60pt `××××` 0.72）。

  ⚠️ **長度閘門是 2026-08-25 拿掉的**：原本寫「≤3 字」，於是**大字的整條亂碼完全沒人守**——一條 36pt 的公式帶讀成 `OtSat$Set`、一排 60pt 的 `××××`，正是「可編輯的誤讀塗掉好好的點陣」最顯眼的那種。五份 deck 量過：分數低於 0.75 的純拉丁行**全部 31 行都是垃圾**，而剛好在門檻上方那一帶則是真內容（`JR. PAC-MAN` 0.85、`EVOLUTION&OPTIMIZATION(8YEARS)` 0.84、`Level O` 0.85）——所以動的是長度，不是門檻。⚠️ 這條只對**純拉丁**行成立：中文行 0.75 以下多半仍讀得出正確的詞（頁面詞彙校正救得回來），拉丁行不會。

  **門檻判不動的高分孤立殘黨用「雜訊鄰域擴散」收**：弱行（≤9pt，或 ≤2 字無 CJK 且 ≤20pt）若 2×行高內有已丟行、又沒有強行（非弱的保留行）鄰居 → 一起丟，迭代到不動點 — 命盤的 m/Ⅱ/10 分數 0.96+ 純門檻看不出來、靠這個收掉；p8 `IP` 因緊貼 `Attacker` 活下來；p9 五個 8pt 時間戳是同一條弱行鏈、一個跌破 0.94 會整鏈沖掉（整條時間軸一致留原圖，可接受）。

  **第三遍「孿生一致性」**（使用者指示 2026-06-12）：同組籌片丟一半比全丟／全留都醜（p9 BSP 四層堆疊：商業策略／資訊策略 0.60–0.69 被丟、應用系統／技術基礎 0.77+ 活下來 → 半蓋板半原圖）— 保留中 ≤14pt 的行若與已丟行是孿生（同 snap 字級、同欄 x 重疊 ≥60%、高度差 ≤30%、垂直間距 ≤0.8 行高）就跟著丟，與擴散同一個迭代迴圈跑到不動點（也順手收掉 p10 書架上漏網的 System Design 書脊）。丟掉的行完全不產生形狀、原圖點陣字直接外露。

- **書封／告示牌式斜排裝飾字成對丟棄**：兩行 |角度| ≥15°、皆無 CJK、旋轉矩形互相交疊（**雙方坐標系都要檢查**）→ 整對留原圖 — p10 書脊 VENDOR PITCH DECK 被拆成 −28° 的 VENDO ＋ PITCH DECK 交疊框，後畫的蓋板塗掉先畫的點陣字；VENDO 本身就是截斷誤讀，可編輯價值為零。**CJK 豁免**：斜置金字塔籌片是真內容。
