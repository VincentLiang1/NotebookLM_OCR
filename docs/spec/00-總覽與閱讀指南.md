# 系統設計與開發規格書 — 總覽與閱讀指南

> **這份規格書是什麼**：一套足以讓「沒有看過原始碼的開發者（或 AI）」從零重建出整個系統的規格——**所有規則、所有門檻、所有反例**，以及每一條規則背後的實測依據與被推翻過的前一版結論。
>
> **這份規格書不是什麼**：不是使用手冊（那是 `README.md`），也不是十分鐘看完的架構導讀（那是 `docs/系統規格.md`）。

---

## 0.1 產品的一句話定義

**把純影像的 NotebookLM 簡報 PDF，變成可以在 PowerPoint 裡直接編輯的 .pptx。**

每一頁以全解析度的頁面渲染圖當背景，疊上實心填色矩形蓋住點陣文字，再放上可編輯、樣式比對過的文字——字級、粗體、文字色、蓋板色**全部從影像估計**，沒有任何一項來自 PDF 的文字層（來源 PDF 根本沒有文字層，那正是這個專案存在的理由）。

取代的是 deckedit.com 這個線上服務。專案代號 **NotebookLM_OCR**，CLI 是 `pdf2ppt.py`。

## 0.2 規格書的撰寫立場

| 面向 | 立場 |
| --- | --- |
| **技術棧** | **綁現行實作**。正文直接以 Python 3.14 / PyMuPDF / RapidOCR / python-pptx 描述，模組名與函式名直接出現。理由：本專案的價值幾乎全在「這個門檻為什麼是這個值」，而那些理由與 RapidOCR 偵測框的行為、與 Microsoft YaHei 的字寬綁死，抽象成技術中立的敘述只會失真。 |
| **參數與門檻** | **一律視為規格，不是實作細節**。每個數值都附上實測樣本、反例，以及被推翻過的前一版結論。重建時照抄；要改必須重跑對應的四份 deck 回歸。 |
| **「為什麼」與「反例」** | **與「做什麼」同等重要，而且反例比規則更重要**。這個專案的每一條規則都同時是「抓得到 A」與「不會誤殺 B」的平衡點——少了 B，重建者會在第一次重構時把門檻放寬，然後重演同一場災情。本規格書大量出現「曾設 X 誤殺 Y」，那些句子是規格的一部分。 |
| **被否決的路** | **和被採用的路一樣重要**，獨立成節（§11.2）。有十幾條方向正確、直覺上該做、實際量過不成立的改進；不寫下來的話，每個接手的人都會再做一次。 |
| **通用性** | §1.2 的「最高原則」凌駕於本書其他所有內容之上：**任何只對某一份 PDF 有效的規則都不合格**。 |

### 規範用語

- **必須（MUST）**：違反即為不符合規格。
- **不得（MUST NOT）**：違反即為不符合規格，通常伴隨已知的災情。
- **應該（SHOULD）**：有充分理由才可偏離，偏離要留下記錄。
- **可以（MAY）**：實作者自由選擇。

本書沿用專案既有的標記：**⚠️ 開頭的段落是踩過的坑**，不是提醒事項。

## 0.4 重建路徑（建議順序）

照這份規格從零建一次的話，建議照這個順序——**每一階段都能獨立驗收**：

| 階段 | 內容 | 對應章節 | 驗收 |
| --- | --- | --- | --- |
| **A. 骨架** | 兩套座標系、三個資料結構、`FONT_SIZES` | 02 | — |
| | 渲染 @200dpi → OCR → 一行一個形狀，先不估任何樣式 | 02、03 | 文字全部出現在對的位置 |
| **B. 能看的輸出** | 字墨帶量字級（`CJK_INK_RATIO`）、環帶取底色、蓋板 | 04、06 | 蓋得住點陣、字級大致對 |
| | 粗體三段判別 | 05 | |
| **C. 讓它不出錯**<br>（最大、最多實測記錄） | 字級調和的六個 pass ⚠️ **順序是契約，見 §2.6** | 04 | 同段折行、同卡堆疊、同列並排都同級 |
| | 投影（glow）與蓋板裁切 | 06 | 放大到 200dpi 看不到色差接縫或殘墨 |
| | OCR 文字修正的十四條 | 03 | |
| **D. 該放棄的就放棄** | `drop_unreproducible`、`drop_illegible_lines`、浮水印 | 07 | 插圖裡的雜訊行留原圖，不會轉成錯字蓋板 |
| **E. 邊角** | 弧形、直排、旋轉、雙色橫幅、上標、刪除線 | 06、07、08 | |

⚠️ **不建議先做階段 C**：那些調和 pass 全部是「兩行本來就該同級卻不同級」的修正，沒有 B 產出的字級就沒有東西可以調和；而且它們的每一個門檻都是拿 B 的實測散佈校準的。

⚠️ **階段 D 的價值容易被低估**：把插圖裡的 8pt 亂碼轉成可編輯文字，結果是「錯字蓋板」——**比留原圖更糟**。這是本專案少數「不做比做好」的地方。

## 0.5 這份規格書最重要的十條

如果只能記住十件事，是這些。每一條都在對應章節有完整說明與實測依據。

1. **所有調整必須具通用性**。每一條規則都必須對「未來任意新的 NotebookLM 簡報 PDF」有意義；嚴禁針對單一頁面或單一字串硬編碼。唯一例外是已知無誤殺空間的辭典型修正。（§1.2）
2. **偵測框的留白不一致，任何「用框高的倍數去猜」的做法遲早會壞**。這是本專案第二重要的不變量。字級由**字墨帶**量、浮水印遮擋範圍由**掃描**量、蓋板由**字墨界**推——全都不看框。（§2.2、§4、§7）
3. **兩套座標系**：影像 px @200dpi，投影片固定 960 pt 寬。`px_to_slide_pt = 960 / img_width`。（§2.1）
4. **投影（glow）同時污染表面色與蓋板幾何**。這類簡報給文字加了一層 10–20px 的柔和暗影：它會讓環帶取樣偏暗（蓋板深一階）、讓蓋板留下暗框、讓行與行之間留一條縫。解法是「往外走到顏色穩定才承認那是表面」，走了幾段就是投影半徑。（§6）
5. **同家族字級寧可一致也不要混雜**（使用者 2026-06-13 裁定）。這條衍生出四個 pass：`harmonize_font_sizes`、`sync_clamped_twins`、`propagate_column_clamp`、`propagate_row_clamp`。並排的拖動必須是**多數決**，否則一次誤夾會放大成一整列。（§1.4、§4）
6. **`cli.py` 的 pass 順序是契約**。至少三條規則的正確性依賴誰先誰後：`harmonize_stacked_overlap_size` 必須在 `harmonize_font_sizes` 之前（否則調和把已修正的字級併回去），粗體投票必須在字級調和之後（否則隊列不乾淨），裁切必須在畫形狀之前。（§2.6）
7. **`--cover` / `--no-cover` 只決定「色塊畫在哪」，不是精緻度開關**。裁切、分段蓋板、弧形切線段三件事**兩種模式都要做**；`--no-cover` 的色帶還比字墨高 0.20em（PowerPoint 的行首 leading 補償），裁切必須知道。**2026-08-24 起預設是 `--no-cover`**，理由是可維護性而非外觀——兩者的視覺差異在肉眼閾值以下。（§6）
8. **每一次破壞「字元 1:1 對應」的文字轉換，都必須把 `char_boxes` 設成 `None`**。逐字顏色、空格還原、上標偵測全靠它，留著錯的比沒有更糟。（§2.2、§3）
9. **不要用「參考 PPTX」校準樣式**。它的粗體／字級旗標是從我們自己更早的輸出繼承來的，我們漏判的粗體在它裡面同樣是錯的。**樣式的真值只有一個：PDF 渲染圖的目視比對。**（§10.1）
10. **改動的驗證方式是四份 deck 全跑、逐行零差異**。目視絕對看不出來的回歸（16 行底色漂移 7–14 個單位、一條規則翻掉另一條規則的弱鄰域擴散）全部是這樣抓到的。（§10.3）

## 0.6 與既有文件的關係

這份規格書**不取代**下列文件，它們各自服務不同的讀者：

| 文件 | 讀者 | 關係 |
| --- | --- | --- |
| `README.md` | 使用者 | 安裝、操作、選項表、限制 |
| `CLAUDE.md` | 維護這份程式碼的 AI／開發者 | **硬規則與指路**，每次對話自動載入 |
| `docs/系統規格.md` | 維護者 | 現行程式碼的**架構導讀**（十分鐘看完模組之間怎麼接） |
| `docs/dev/collaboration.md` | 維護者 | 協作方式的沿革、災情紀錄、規則的來歷 |
| **`docs/spec/`（本文件）** | **重建者** | **從零建一次需要知道的一切** |

⚠️ **為什麼要把 78 條規則從 `CLAUDE.md` 搬出來**：`CLAUDE.md` 每次對話都會整份載入，那 78 條長篇規則佔掉大量 context，而其中絕大多數在任何一次對話裡都用不到。搬出來之後 `CLAUDE.md` 只留「規則本身 + 門檻 + 程式指路 + 詳見連結」，需要細節時才讀對應章節。**內文一個字都沒改**——這些句子的價值全在細節（門檻、反例、被推翻的前一版），改寫成摘要等於毀掉它們。

⚠️ **常數的正典永遠是程式碼**。這份規格與 `CLAUDE.md` 都是它的整理版，兩份副本必然會漂——**這件事在本專案已經發生過**：`CJK_INK_RATIO` 在 commit `4c97794` 改成 0.875，`CLAUDE.md` 還寫著 0.91，隔了兩個多月沒人發現，最後是 `tests/test_docs.py` 上線第一次執行抓到的。
