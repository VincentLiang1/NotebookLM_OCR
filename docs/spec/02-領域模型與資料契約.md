# 2. 領域模型與資料契約

整條管線只有三個資料結構在流動，全部定義在 `pdf2ppt/models.py`。這一章是它們的契約：每個欄位是誰寫的、誰讀的、什麼時候會變成 `None`。

## 2.1 兩套座標系（最容易搞混的一件事）

| 空間 | 單位 | 誰用 |
| --- | --- | --- |
| **影像像素** | px @ 200dpi | `render.py` 的輸出、所有 OCR 框與影像分析（`style.py` 幾乎全部）、`Line.bbox`、`Style.ink_*_px` |
| **投影片點** | pt，版面固定 12192000 EMU = **960 pt** 寬 | `Style.font_pt`、`est_pt`、`max_fit_pt`、`clamp_pt`、`builder.py` 寫進 XML 的一切 |

換算常數只有一個：

```python
px_to_slide_pt = 960.0 / img.shape[1]
```

⚠️ **PDF 頁面可以是任何實體尺寸**（範例 deck 是 1376×768 pt = 19.1 吋寬），但投影片一律 960 pt 寬。所以「字級」永遠要換算到投影片點數空間，**不能拿 PDF 的點數直接用**。

## 2.2 `Line` — 一行 OCR 結果

| 欄位 | 型別 | 契約 |
| --- | --- | --- |
| `text` | `str` | 已經過空格還原、盤古之白、標點復原、簡繁修正、圓點正規化。**每一次破壞「字元 1:1 對應」的轉換都必須把 `char_boxes` 設成 `None`** |
| `bbox` | `(x0,y0,x1,y1)` px | 軸對齊外框。⚠️ **留白不一致**，不可拿來當字級來源；行首圓點復原會把左緣往左延伸 |
| `score` | `float` | 辨識信心。0.8 是「可信」的門檻（`_page_vocab`、`_emits_simplified` 都用它）；`drop_illegible_lines` 用更細的分級 |
| `angle` / `center` / `size` | 旋轉資訊 | 偵測器回傳旋轉 quad，或旋轉救援成功時填。**單一字形的角度一律丟棄**（沒有基線就沒有方向） |
| `char_boxes` | `[(char,l,t,r,b)]` 或 `None` | 對應**去空格後**的 `text`。CTC 邊緣不準（見 03 章的空格還原） |
| `arc_sagitta` | `float` | 弧形文字的弧深，正值為上拱 |

## 2.3 `Style` — 一行的樣式估計

`estimate_style()` 產出，之後被 `blocks.py` 的十幾個調和 pass 修改，最後由 `builder.py` 消費。

**尺寸類**

| 欄位 | 契約 |
| --- | --- |
| `font_pt` | 最終字級，必為 `FONT_SIZES` 的成員。**這是唯一會被 blocks.py 的 pass 反覆改寫的欄位** |
| `est_pt` | snap 前、**寬度夾制後**的估值。折行調和拿它判斷「兩行是不是真的同級」——不可改用 snap 後的值（兩行落在折點兩側時差一整階） |
| `max_fit_pt` | **投影片右緣**這個硬天花板。⚠️ 只有它可以放進來；障礙夾制不行（見 `clamp_pt`） |
| `clamp_pt` | **障礙**（格線、卡框、牽引線圓點）給的天花板。與 `max_fit_pt` 分開存，是因為折行組統一時兩者的處理不同 |
| `ink_top_px` / `ink_bottom_px` | 真正的字墨上下界。**被切的字形會走出框外**，所以它們未必落在 `bbox` 內 |
| `glow_px` | 文字投影往外延伸多遠。0 = 沒有投影。蓋板的 pad 與水平外擴都吃它 |

**顏色類**

| 欄位 | 契約 |
| --- | --- |
| `text_rgb` | 筆畫核心色（離底色最遠的前 30% 墨水像素平均） |
| `bg_rgb` | 蓋板色。`None` = 估不出來（漸層／照片／插畫區）→ **不畫蓋板**，文字透明疊在原圖上 |
| `runs` | 多色行的 `[(字數, rgb), …]`，涵蓋去空格後的文字 |
| `bg_segments` | 雙色橫幅的 `[(x0,x1,bg), …]`。⚠️ `bg_rgb` 只記**最右段**的顏色，所以有 segments 時**兩種 cover 模式都要畫分段蓋板** |

**幾何覆寫**

| 欄位 | 契約 |
| --- | --- |
| `cover_band_px` | `(y0,y1)`，蓋板實際塗的垂直範圍。`None` = 由字墨帶推導。**由 `builder._trim_stacked_overlaps` 寫入**——裁切必須寫這個而不是改字墨界，否則 builder 會把剛買到的間隙又還回去 |
| `cover_x0_px` / `cover_x1_px` | 水平**收窄**（不是外擴）：框緣外溢到鄰近彩色圖示時用 |

**旗標類**：`bold`、`vertical`、`strikethrough`、`superscript_tail`、`highlight_removed`、`stroke_rel`、`bold_r`。

⚠️ **`runs`／`superscript_tail`／`strikethrough` 在 builder 都必須加 `len(block.lines) == 1` 閘門**：合併後的 block 只保留第一行的 style。

## 2.4 `TextBlock` — 一個輸出形狀

`lines`（一或多行）＋ `style` ＋ `align`，`bbox` 是所有行的聯集。`_bbox` 可被裁切 pass 覆寫。

`--merge-lines` 之外，預設**一行一個 block**（與 DeckEdit 相同）。

## 2.5 `FONT_SIZES` — 唯一的字級階梯

```python
[8, 9, 10, 10.5, 11, 12, 14, 16, 18, 20, 24, 28, 32, 36, 40, 44, 48, 54, 60]
```

⚠️ 60 是**上限**：p15 的步驟徽章數字真實字級約 105pt，三個都被壓到 60。這是已知限制，不是 bug。

## 2.6 管線順序（`cli.py`）

順序本身就是契約——好幾條規則的正確性依賴「誰先誰後」：

```
render → OCR → estimate_style（逐行）
  → 浮水印過濾
  → drop_unreproducible → drop_illegible_lines
  → merge_row_title_fragments
  → harmonize_stacked_overlap_size   ← 必須在 harmonize_font_sizes 之前
  → harmonize_font_sizes             ← 字級先調和，粗體隊列才乾淨
  → harmonize_code_block_latin
  → sync_clamped_twins
  → propagate_column_clamp
  → propagate_row_clamp
  → reeval_clamped_bold → harmonize_bold   ← 只在 bold_mode == auto
  → harmonize_across_dropped
  → clamp_row_neighbors
  → harmonize_chip_bg
  → lines_to_blocks → builder.add_slide
```

`builder.add_slide` 內部再跑 `_trim_row_overlaps` → `_trim_stacked_overlaps`，然後才畫形狀。
