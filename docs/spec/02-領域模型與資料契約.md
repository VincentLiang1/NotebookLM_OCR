# 2. 領域模型與資料契約

整條管線只有三個資料結構在流動。這一章是它們的契約：每個欄位由誰寫、由誰讀、什麼時候會是「沒有值」。

⚙️ **動任何資料結構或管線順序之前請先讀完這一章。** 實作上的落點（模組、類別、函式名）在 §12。

## 2.1 兩套座標系（最容易搞混的一件事）

| 空間 | 單位 | 誰用 |
| --- | --- | --- |
| **影像像素** | px @ 200dpi | 頁面渲染圖、所有 OCR 框、所有影像分析（樣式估計幾乎全部）、`Line.bbox`、`Style` 的 `ink_*_px` |
| **投影片點** | pt，版面固定 12192000 EMU = **960 pt** 寬 | `Style.font_pt`、`est_pt`、`max_fit_pt`、`clamp_pt`，以及寫進 PPTX 的一切 |

換算常數只有一個：

```
每一影像像素折合的投影片點數 = 960 ÷ 渲染圖寬度(px)
```

⚠️ **PDF 頁面可以是任何實體尺寸**（範例 deck 是 1376×768 pt = 19.1 吋寬），但投影片一律 960 pt 寬。所以「字級」永遠要換算到投影片點數空間，**不能拿 PDF 的點數直接用**。

## 2.2 `Line` — 一行 OCR 結果

| 欄位 | 型別 | 契約 |
| --- | --- | --- |
| `text` | 字串 | 已經過空格還原、盤古之白、標點復原、簡繁修正、圓點正規化。**每一次破壞「字元 1:1 對應」的轉換，都必須把 `char_boxes` 清成「沒有值」** |
| `bbox` | `(x0,y0,x1,y1)` px | 軸對齊外框。⚠️ **留白不一致**，不可拿來當字級來源；行首圓點復原會把左緣往左延伸 |
| `score` | 浮點數 | 辨識信心。**0.8 是「可信」的門檻**（頁面詞彙校正與「這頁的模型在滑」的確認都用它）；丟棄規則用更細的分級（見 §7） |
| `angle` / `center` / `size` | 旋轉資訊 | 偵測器回傳旋轉四邊形時填，或旋轉救援成功時填。**單一字形的角度一律丟棄**——沒有基線就沒有方向（見 §7） |
| `char_boxes` | `[(字元, 左, 上, 右, 下)]` 或「沒有值」 | 對應**去空格後**的 `text`。CTC 的字框邊緣不準（見 §3 的空格還原） |
| `arc_sagitta` | 浮點數 | 弧形文字的弧深，正值為上拱 |

## 2.3 `Style` — 一行的樣式估計

由**樣式估計**逐行產出，之後被十幾個調和 pass 反覆修改，最後由**輸出階段**消費。

**尺寸類**

| 欄位 | 契約 |
| --- | --- |
| `font_pt` | 最終字級，必為字級階梯（§2.5）的成員。**這是唯一會被調和 pass 反覆改寫的欄位** |
| `est_pt` | snap 前、**寬度夾制後**的估值。折行調和拿它判斷「兩行是不是真的同級」——不可改用 snap 後的值（兩行落在折點兩側時差一整階） |
| `max_fit_pt` | **投影片右緣**這個硬天花板。⚠️ 只有它可以放進來；障礙夾制不行（見 `clamp_pt`） |
| `clamp_pt` | **障礙**（格線、卡框、牽引線圓點）給的天花板。與 `max_fit_pt` 分開存，是因為折行組統一時兩者的處理不同 |
| `ink_top_px` / `ink_bottom_px` | 真正的字墨上下界。**被切的字形會走出框外**，所以它們未必落在 `bbox` 內 |
| `glow_px` | 文字投影往外延伸多遠。0 = 沒有投影。蓋板的垂直 pad 與水平外擴都吃它 |

**顏色類**

| 欄位 | 契約 |
| --- | --- |
| `text_rgb` | 筆畫核心色（離底色最遠的前 30% 墨水像素平均） |
| `bg_rgb` | 蓋板色。「沒有值」= 估不出來（漸層／照片／插畫區）→ **不畫蓋板**，文字透明疊在原圖上 |
| `runs` | 多色行的 `[(字數, rgb), …]`，涵蓋去空格後的文字 |
| `bg_segments` | 雙色橫幅的 `[(x0,x1,bg), …]`。⚠️ `bg_rgb` 只記**最右段**的顏色，所以有 segments 時**兩種 cover 模式都要畫分段蓋板** |

**幾何覆寫**

| 欄位 | 契約 |
| --- | --- |
| `cover_band_px` | `(y0,y1)`，蓋板實際塗的垂直範圍。「沒有值」= 由字墨帶推導。**由堆疊裁切寫入**——裁切必須寫這個覆寫欄位，而不是去改字墨界；否則輸出階段會照字墨帶把色帶重新推導一次，把剛買到的間隙又還回去 |
| `cover_x0_px` / `cover_x1_px` | 水平**收窄**（不是外擴）：框緣外溢到鄰近彩色圖示時用 |

**旗標類**：`bold`、`vertical`、`strikethrough`、`superscript_tail`、`highlight_removed`、`stroke_rel`、`bold_r`。

⚠️ **`runs`／`superscript_tail`／`strikethrough` 在輸出階段都必須加上「這個 block 只有一行」的閘門**：合併後的 block 只保留第一行的樣式。

## 2.4 `TextBlock` — 一個輸出形狀

`lines`（一或多行）＋ `style` ＋ `align`。`bbox` 是所有行的聯集，且**可被裁切 pass 覆寫**。

除非要求合併行，否則預設**一行一個 block**（與 DeckEdit 相同）。

## 2.5 字級階梯 — 唯一的字級來源

輸出字級只能落在這個階梯上：

```
8, 9, 10, 10.5, 11, 12, 14, 16, 18, 20, 24, 28, 32, 36, 40, 44, 48, 54, 60
```

⚠️ 60 是**上限**：p15 的步驟徽章數字真實字級約 105pt，三個都被壓到 60。這是已知限制，不是 bug。

## 2.6 管線順序

順序本身就是契約——好幾條規則的正確性依賴「誰先誰後」：

```
渲染 → OCR → 逐行樣式估計
  → 浮水印過濾
  → 丟棄無法忠實還原的行 → 丟棄太小／太模糊的行
  → 合併同列被拆開的標題碎片
  → 統一同卡堆疊標籤的字級        ← 必須在折行字級調和之前
  → 折行字級調和                  ← 字級先調和，粗體隊列才乾淨
  → 程式碼行的拉丁段夾制
  → 被夾制的標題拖動同款孿生
  → 同欄字級傳遞
  → 同列字級傳遞（多數決）
  → 被夾後重判粗細 → 粗體隊列投票  ← 只在粗體模式為 auto
  → 跨丟棄行的樣式對齊
  → 同列右鄰寬度夾制
  → 同晶片堆疊共用底色
  → 行 → 形狀 → 產生投影片
```

產生投影片時，內部再跑**同列裁切 → 堆疊裁切**，然後才畫形狀。

⚠️ 三條硬順序（違反其一就會出現看得見的錯）：

1. **統一同卡堆疊標籤的字級，必須在折行字級調和之前**——否則調和會把已經修正過的字級再併回去。
2. **粗體判定必須在字級調和之後**——隊列是照「同頁同字級」組的，字級還沒穩定時隊列不乾淨。
3. **裁切必須在畫形狀之前**——裁切改的是蓋板幾何，形狀畫下去就來不及了。

各 pass 對應的實作函式名見 §12.3。
