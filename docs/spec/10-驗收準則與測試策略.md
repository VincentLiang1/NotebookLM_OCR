# 10. 驗收準則與測試策略

⚙️ **改完任何一條規則、要驗收之前請先讀完這一章。** 照著打就能跑的指令、語料路徑與清掃 glob 見 `docs/dev/verification.md`。

## 10.1 這個專案能自動測什麼、不能自動測什麼

| 層次 | 有沒有自動測試 | 為什麼 |
| --- | --- | --- |
| **文件與程式碼的一致性** | ✅ 有 | 常數值、指路、CLI 旗標三方一致、否決索引——機器驗得到 |
| **轉換品質**（字級對不對、蓋板蓋乾淨沒有） | ❌ **沒有，也很難有** | 真值是「跟原稿長得一不一樣」。沒有一份標好答案的語料，而輸出是 24MB 的簡報檔 |
| **回歸**（這次改動有沒有動到不該動的） | ⚠️ 半自動：逐行對照 | 這是實務上最有效的一招，見 §10.3 |

⚠️ **不要試圖用「參考簡報」當品質基準**：那份參考檔的粗體／字級旗標往往是從我們自己更早的輸出繼承來的（使用者只修文字、不修樣式），**我們漏判的粗體在它裡面同樣是錯的**。樣式的真值只有一個：**PDF 渲染圖的目視比對**。

## 10.2 文件一致性測試守什麼

守四類會**靜默腐爛**的東西：

1. **文件引用的常數值** —— 第一次執行就抓到 `CJK_INK_RATIO`：程式在 commit `4c97794` 改成 0.875，`CLAUDE.md` 還寫著 0.91，隔了兩個多月沒人發現。
2. **指路**（檔名、模組、函式名）—— 第一次執行也抓到 `CLAUDE.md` 還提著一個當天稍早剛刪掉的函式。刻意的歷史記述放進白名單，**白名單自己也被斷言守著**。
3. **CLI 旗標三方一致** —— 命令列參數定義是正典，說明文件的選項表與圖形介面的控制項都是手抄的。
4. **索引與地圖** —— 「量過而否決的路」指到的標題還在不在；規格書的章號連號、地圖與目錄一一對應。

另有一條 meta 測試守**抓法本身**：引用寫法一改，常數那條會變成「零個全過」的空綠燈——**那比沒有測試更糟**，因為它看起來在守東西。

⚠️ **這一支不驗語意**：它不知道某條規則講得對不對，只知道文件裡那個數字與程式裡那個數字是不是同一個。語意的真值仍然只有 §10.4。

## 10.3 回歸的做法：四份 deck 全跑、逐行對照

這是實務上唯一有效的回歸手段，2026-08-23 那一整輪的每一次驗證都靠它。

**做法**：改動前先跑一輪存成基準，改完再跑一輪，比對每一行的文字、字級、粗細、底色、文字色與 snap 前估值。**預期是零差異**——有差異的每一行都要能說出為什麼，說不出來就是回歸。

**它抓到過什麼**（都是目視絕對看不出來的）：

- 一個 +3px 的取樣半徑讓 **16 行底色漂移 7–14 個單位**，其中數行整個落到鄰近表面（`Transformer_演進地圖` p2 `Pre-RMSNorm` 248→234、p4 的 K 籌片）。
- 一個「沿著字墨走出框外」的規則讓 `Transformer_演進地圖` p1 的 9pt `Sparse` 變成 11pt，**翻掉了丟棄規則的弱鄰域擴散**，一口氣救回七個本該留原圖的圖表標籤。
- 一整輪的純清理（八份手抄收斂成三個共用述詞、色彩眾數改用計數桶、光暈走到穩定就停）達成**文字、字級、粗體、底色、估值、投影半徑全數零差異**——**這才是「純清理」的證明**。

**語料**：`AI_Quality_Guardrails`、`Transformer_演進地圖`、`The_GPT_Blueprint`、`Reinforcement_Learning_Blueprint`。

⚠️ **p-編號有兩種來源**：p11–p15 那批新的（藍籌片投影、橘色橫幅、五張並排卡片、步驟徽章「2」）指的是 `AI_Quality_Guardrails`；早期的（p5 Git Hook、p8 單一/主專案、p13 第三階段、p14 啟動【技術解法】…）指的是**已經不存在的來源檔**，那批案例**再也無法回歸測試**，只剩文字記錄。2026-08-23 那輪 code review 就因此無法驗證其中一條門檻的餘裕。

## 10.4 視覺驗證（樣式的唯一真值）

把輸出的投影片匯出成 PNG，與頁面渲染圖上下並排比對。

⚠️ **要看色差時必須匯出 200dpi 的原尺寸**（3823×2134）；用預設的 1376 寬會把幾個單位的色差糊掉，而本專案好幾條規則的成敗就在那幾個單位（§6.1）。

## 10.5 收尾清掃

⚠️ **這條失守過兩次**（2026-06-12、2026-06-14），兩次成因一模一樣：憑記憶手打一條片段的刪除指令，漏掉除錯疊圖。而版控忽略清單已經涵蓋這些檔，所以 **`git status` 看起來乾淨、把殘留藏起來了**。

**乾淨的 git status 不等於乾淨的工作目錄。** 每一輪的**最後一個動作**跑一次完整掃描，並且**用一次目錄列出來目視確認**——那一步才是抓得到「漏掉一個 glob」的那一步。

⚠️ **永遠不要刪要交給使用者驗收的產出**；臨時檔一律寫到暫存目錄，不要落在專案裡。
