# 4. 流程-字級估計與寬度夾制

字級是這個專案最難的一塊：**偵測框的留白不一致**，所以不能用框高；字墨帶高度又有 ±3px 的模糊雜訊，而 snap 折點就在雜訊裡面。本章分兩半：**量**（字墨帶、逐字 CJK 共識、被切的字形）與**夾**（三級寬度天花板、足跡檢查、各種同族調和）。

⚙️ **動到字級／寬度估計，或任何一個字級調和 pass 之前請先讀完這一章。** 實作上的落點（模組、函式名）見 §12。

> 這些條目原本住在 `CLAUDE.md` 的「架構」章，2026-08-23 搬進規格書；2026-08-24 改寫成技術中立，門檻、實測數據與反例一字未動。

## 4.1 字級從字墨量，不從框量

- **兩套座標系**：PDF 頁面可以是任何尺寸（範例：1376×768 pt = 19.1 吋寬），但投影片固定為 12192000 EMU（960 pt）寬。字級必須換算到「投影片」點數空間（見 §2.1）。

- **字級來自字墨而非 OCR 框**：偵測框的留白不一致。量測框內緊貼字形墨水的高度，再除以 `CJK_INK_RATIO = 0.875`（用 PowerPoint COM 實際渲染輸出、回測墨水高度所得的實證值；原本是 0.91，commit `4c97794` 重新校準成 0.875 而文件漏改，2026-08-23 由文件一致性測試首次執行時拓出）。

  字墨列要**分群取最重的群**（空隙 > 8px 即切群；行內真實空隙如 i 的點 ≤ ~4px）— 跨進框內的外來墨水會灌高字墨帶、放大字級、讓蓋板塗掉鄰近內容：膠囊框線的圓角／反鋸齒列佔寬 < 0.85 混進字墨（`images/` 案例：離主帶 16 空白列）；上一行的底線 `_` 與下一行的字頂也會壓進框內（`graph.sh` 案例：各離主帶 9 空白列，門檻曾是 0.12×框高＝11.4 而漏切）。

- **密集粗體字墨帶不可被 `MAX_INK_ROW_FRAC` 切碎**（使用者回報 2026-06-14）：`MAX_INK_ROW_FRAC=0.85` 是用來剔除「整列幾乎全是墨」的 ribbon 背景列，但**密集粗體文字在其最擠的中段列也會超過 0.85**（p14 白色粗體「Redmine 工單開立與完成時間戳」峰值 0.90、「全力建構內部 Codebase Skill」0.94，真實心 ribbon 才 ~1.0），這些列被剔除後在字墨帶中間打洞、分組把帶切成碎片、只剩一小片 → 量成 6–10pt（該行其實是填滿框的 24pt 大字）。

  **修法**：仍把近實心列從帶的列集合剔除，但分組時**只在「真正空白縫（>8 列無任何字墨）」切組、橋接被上限剔除的近實心列**（跨距含被橋接的密集列）。對正常行（無近實心列）與舊的鄰行分離案例（`graph.sh` 9 空白列、`images/` 16 空白列）邏輯完全等價——它們本就由空白縫分隔。連帶修好 p13 金色塊（第二階段：試點 從 10.5pt 救回、漏偵測的「同步補強 DORA 地基」也回來了）。

- **行首高圖示要從字墨帶剔除**（使用者回報 2026-06-13）：偵測框吞進文字左側的高圖示會灌高字墨帶、放大字級。p6 檔案樹每個檔名左邊有文件圖示，`index.md`／`log.md`／`CLAUDE.md`／`style_guide.md` 把圖示框進去量成 24/20/18/24pt，而圖示落在框外的同款檔名（`meeting_notes.md` 等）正確量成 12pt。

  用 `char_boxes` 框出真字範圍：行首間隙（框左到第一字）內的字墨若明顯**比文字帶高**（h_lead > 1.25×h_text）即判圖示——把該段從字墨帶清掉（字級＋蓋板高都據此），並設 `cover_x0_px` 讓圖示**不被蓋掉**（點陣圖示保留、可編輯文字對齊原稿而非塞進圖示位）。char box 內縮幾 px，故向左走到真正字緣（停在圖示前的空白縫）再定蓋板左界（p6 `CLAUDE.md` 的 C 點陣起點在框左外 9px、貼 char box 會露出一條）。自限性：正常行第一字緊貼框左、清除區為空。全文僅這 4 個檔名觸發。

## 4.2 混合行的逐字 CJK 共識

- **混合行（中英夾雜）字級取逐字 CJK 共識**：拉丁降部（g/p/y、括號、/）會伸到表意字帶底下約 0.15 em，整行字墨高除以 `CJK_INK_RATIO` 會灌高字級（第 4 頁「`graph.sh` 使用」：66px vs 純 CJK 同級行 58px → 18pt 應為 14pt）。

  每個 CJK 字各開欄窗測列範圍，**過半字落在中位數 ±4% 內才採叢集最大值，否則退回全字最大值**（±2% 曾因正常字形差異讓叢集空集、退回 max 撿到被上行降部污染的字：p14「轉化為 AI 的 Guardrails」[80,75,93,75] 量成 24pt；±4% 仍排除 5% 的模糊突起）——叢集規則同時剔除「鄰行墨水灌進單一字窗」（出 +14%）與「模糊突起」（序／譜 61px vs 四個同伴 58px，恰好跨 14/16pt 折點）；退回規則保住共識不足的雜訊行（12pt 的周郁凯字高散佈 39–47px，硬套中位數會錯殺正確的 47）。

  實作要點：欄窗由**逐字 advance 寬度**按比例映射到框寬 — CTC word box 太抖不能用（「使用」的字框偏移半個字、量出 33px）；每字窗內縮 0.2 em；低墨全形標點（（）：。等）整個欄窗排除（全形（同樣降到帶底下）；窗內列範圍要套同樣的「空隙 >8 切群取最重」（`graph.sh` 框頂 3 列雜墨曾讓它反彈回 18pt）；⚠️ **窄欄窗不可套 `MAX_INK_ROW_FRAC`**（CJK 橫筆畫會貫穿整窗被誤刪成 8pt）；結果以 `min(完整字墨高, 共識高)` 為準。

  **門檻**：含拉丁降部字元的行（可單字錨定），或含拉丁字母且 ≥2 個表意字票的行（p14 案例無降部字元但被上行 p/q 字莖橋接灌高；≥2 票防「2025 年」單字塌縮）。

  ⚠️ **再放寬到所有 CJK 行已試過並回退** — ±3px 模糊雜訊讓其他臨界行掉一階、把原本一致的區塊拆散（p4 右註解 16→16/14/14），單 CJK 字的行（「2025 年」）更會塌到單字高度。「稀疏邊緣列裁切」（< 0.25×中位數）也試過並放棄（曾把 44pt 標題裁成 40pt）。蓋板與文字定位仍用完整字墨範圍 — 降部點陣必須被蓋住。

## 4.3 偵測框切到字形時，沿著字墨走出框外

- **偵測框切到字形時要沿著字墨走出框外**（使用者回報 2026-08-23）：p15 步驟徽章的「2」框只有 209×240，兩個同款兄弟是 248×359／283×389 —— 偵測器把 2 的上弧與底橫都切掉，蓋板因此蓋不住那兩塊點陣（上方露一道弧、下方露一條橫槓），可編輯的 2 還比 1／3 低 64px。

  **判別**：框自己的邊緣列有墨（≥0.15 框寬），且與字墨帶之間**沒有任何空白列**（鄰行殘墨一定隔著空白列，本專案記載的案例都 ≥9 列）。⚠️ **邊緣測試要用「所有存在的字墨列」而不是「已篩選的列集合」**：2 的底橫佔框寬 99%，`MAX_INK_ROW_FRAC` 剛好把它從篩選後的集合剔掉、而切口正在那裡。

  四道防誤判缺一不可：
  - **環帶必須是平整背景**（佔比 ≥`BG_MIN_SHARE`）：漸層晶片上（`Transformer_演進地圖` p8 的青→琥珀「Mixtral 8x7B」膠囊，環帶佔比 0.24）整片晶片對參考底色都算墨水，「字形還在延續」在框外根本沒有意義。
  - **只對字墨帶高 ≥`MIN_CUT_BAND_PX`（60px ≈17pt）的行做**。插圖裡的 8–11pt 標籤四面都貼著圖形，讓它們走出去會改字級 → 丟棄規則的弱鄰域擴散跟著翻盤（`Transformer_演進地圖` p1 的 9pt `Sparse` 變 11pt，一口氣救回七個本該留原圖的圖表標籤）。
  - **走到上限（0.6×字墨帶高）還沒遇到空白列就整個放棄**：那不是被切的字，是緞帶邊或整片填色，跟下去會吞掉半頁。
  - **兩側邊距都有墨的列＝畫出來的線，不是字**（`CUT_MARGIN_PX`=12，兩側各 ≥50%）：表格橫格線與公式根號上橫線天天壓在框邊（`The_GPT_Blueprint` p3 儲存格列、p6 的 √dk）。2 的底橫只佔自己的字寬、兩側邊距乾淨，照樣走得過去。

## 4.4 三級寬度天花板與足跡檢查

- **寬度量測按字種分字型**：混排行的拉丁段用 Arial、CJK 段用 YaHei 分段加總 — 全用 YaHei 量會高估輸出寬度（YaHei 拉丁比 Arial 寬 ~9%），夾制把 p5「Git Hook 自動化」從真實 24pt 掐到 20。單字呼叫與 2 字短串維持原規則。注意**來源字型的拉丁還要再窄 ~14%**，Arial 也吃不下時靠懸崖防護（見下）。

- **寬度天花板分三級、snap 有懸崖防護**：
  - **投影片右緣（硬）**：`(960 − x0 − 3)/em` — p15 主標 60pt／內文 32pt 曾衝出板面（60→54、32→28，折行尾隨組同縮）；存進 `max_fit_pt`、字級調和的組統一尊重。⚠️ **其他天花板都不可放進 `max_fit_pt`**：p12「嚴格的格式約束…」（幻覺 ： 移除後框變窄）的緊夾制曾把三個真 14pt 折行同伴拖到 12。
  - **障礙（近硬）**：餘裕掃描撞到任何障礙 → 容差只給絕對 3.5pt 渲染寬、**停用懸崖防護**：p13 卡片內文 16pt 曾靠相對 1.02 容差＋懸崖防護連手戳穿卡框 80px（21em 長行的 2% = 27px，相對容差在長行上的絕對量失控）；p5 Git Hook 的 24pt 曾把「化」壓上牽引線圓點（使用者否決）— ⚠️ **「物件 vs 牆」分類已試過並移除**：使用者裁定圓點也不可壓，且被夾下來的標題改由「被夾制的標題拖動同款孿生」處理。掃描**全程無障礙（1.5×行高內）回傳無限大、完全不設寬度天花板** — 拿掃描範圍當天花板曾把右側開闊的 p10「AI 逆向掃描」從 24 掐到 20。底色不明時退回字墨寬天花板。
  - **字墨寬（軟）＋懸崖防護**（僅這條路徑有）：最近 snap 階超過天花板 ≤3% **且絕對超寬 ≤3pt**、回退會掉 >10%（20↔24 階距 17%）時，貼上去（p8 舊框架、p12 卡片內文等估值恰在階上的行）。沒有絕對上限時 21em 長行的 3% 一樣失控。

- **標題足跡檢查**（snap 後、僅 ≥`NARROW_MIN_PT` 且 **em ≥10** 的標題）：標題多在開放空間（無天花板）、高度估值又騎在 snap 中點 — p8 標題估 39 上捨成 40、渲染比原始字墨寬 21%、尾端逼近頁緣（原稿是左右等距置中；使用者要求降一級）。snap 後渲染寬 > 字墨 ×**1.07** 且降一階仍 ≥ 字墨 ×0.90 → 取小（p5/p11/p13 同輪抓出；門檻曾設 1.09 漏掉 p1 封面標題 1.072 — 使用者再報；全文未觸發標題都 ≤1.07，p9 1.069 恰好倖存）。em ≥10 是為了 p15 引言塊（em 4–6）：同一真實字級內足跡比散佈 ±8%，短行不可比。

  ⚠️ **全文性的字墨足跡天花板已試過並撤回**：來源 CJK 字距比 YaHei 均勻緊 ~10%，能抓住超寬標題的容差同時會勒死正常內文（1.098）— 曾一口氣降了 56 行。

  **內文（<`NARROW_MIN_PT`）也套足跡檢查、但門檻 1.13**（使用者回報 2026-06-14）：**粗體筆畫加厚字墨帶 ~6%**，把真實 S 級的粗體行高度估值推過 snap 中點到 S+1 階，渲染就比卡片寬一階而溢出（p3 阿姆達爾…的鐵律 1.26、p14 重啟計量 1.14／為釐清方向 1.41、p5 歷史金流牽一髮 1.19、單執行緒 1.25——**全是粗體、全溢出**）。1.13 留給合法內文（非粗體內文足跡全 ≤1.06、粗體但量對的也 <1.13；門檻內只命中過度 snap 的粗體行）；降一階仍 ≥字墨×0.90 才降。粗細在字級之後才算、足跡檢查取不到，但全文比值 ≥1.10 的行皆粗體、非粗體 ≤1.06，故無需粗體閘門。副作用：粗體掉到 ≤24 後可能被模板重判為常規、再被字級調和併入下行（p3 鐵律 →18 失去粗體前綴），視覺仍正確、可接受。

- **右側餘裕掃描可穿透「細且淡」的障礙**：寬 ≤8px 且 Chebyshev 距 <75 的淡裝飾格線放行繼續掃；深色障礙（牽引線圓點、卡片邊框）不論多細都停下 — 放寬到「細就放行」會讓文字長過 p12 的卡片虛線邊框。

- **障礙夾制留邊距、且傳遞給同欄孿生**（使用者指示 2026-06-13）：餘裕掃描撞到障礙時，可用寬度要再扣 `OBSTACLE_MARGIN_PT`=3pt 邊距（文字剛好貼到格線／卡片邊框看起來壅擠，使用者要降一級）、且取消 snap 容差與懸崖防護 — p2 John Gruber 卡片內文（16→14）、p8「VS Code 內建」「Working Copy」貼欄線（24→20）。

  ⚠️ **障礙天花板存進 `clamp_pt` 而不是 `max_fit_pt`**（後者只給投影片硬邊；上面 p12 那條禁止障礙天花板進 `max_fit_pt`）：字級調和器的折行組統一目標同時受 `clamp_pt` 夾制，否則 p2 卡片內文四行 2-2 平手會被中位數重 snap 回 16、再次衝出卡框。

  同欄傳遞（在孿生拖動之後跑）讓被障礙夾下來的標籤把**同欄、同自然 snap 字級、恰高一階、同色同底**的孿生一起拉下並繼承其粗細 — p8 首欄六個工具名原稿全是同級常規體，但 GitHub Web／Obsidian 較短不撞欄線、snap 上去 24 又被 ≥24 規則自動加粗，靠這條跟著 VS Code 內建 降回 20 常規、整欄一致。

- **同列右鄰寬度夾制**（調和器之後跑）：樣式估計的寬度夾制只看自身字墨寬與寬容門檻，偵測器拆開的標題會渲染超寬、擠進右鄰（p14「AI 協作的黃金法則」40pt 渲染 ~336pt 但到「(流程與資產篇)」左緣只有 323pt）。以右鄰左緣為硬上限選最大可容字級；右鄰若是「同款式、同字級、近貼」的孿生（被拆開的同一標題）則同步縮 — 否則拆開的標題會一邊 36 一邊 40。

## 4.5 同族調和

- **同段折行字級調和**（在浮水印過濾後呼叫）：±3px 模糊雜訊跨在 12/14/16pt 折點上，同一段折行的兩行可能折到不同字級（p10「CB 詢圈案例/」12.6pt vs 折行同伴「法規或生辰八字」14.1pt，字形實際同高）。

  垂直緊鄰（間距 −0.6h~0.45h）、x 重疊 ≥40%、粗體／底色／文字色相同、**snap 前估值差 ≤14%** 的行歸入同組（12% 曾差 0.6% 漏掉 p11 的折行對 11.8 vs 13.5；真實 12-vs-14 對差約 19%；⚠️ **底色差門檻是 25 不是 16** — 照片漸層讓折行同伴的底色估值漂移，p7 成果／零／研究 三行量出 180/160/153、曾被 16 拆組折成 18/20/20）。

  組內字級若散落在**相鄰** snap 階上就統一（多數決，平手取組內估值中位數重 snap），但⚠️ **統一目標不可超過組內任一成員的 `max_fit_pt`** — p15 折行對曾被平手中位數重 snap 推回 32、再度衝出投影片。判斷用 `est_pt`（snap 前、寬度夾制後的估值），不能用 snap 後值 — 兩行落在折點兩側時 snap 後差一整階。這個 pass 修掉的不一致橫跨 7 頁（觸發 Git Commit、N 個/Subagent、橘色[對比] 與另三色籌片、p15 終端機框四行等），全部經視覺驗證。

  **純字級觸發的自動粗體（≥24pt、無筆畫／模板量測）不可擋住折行歸組、且組統一字級掉到 24 以下時要撤粗**（使用者回報 2026-06-13）：短的折行尾以真實未夾制字級渲染、長的折行首被投影片邊緣夾下（p15「物「準確且持續成長的表徵」。」「連結與維護。」量出真 24、其長折行首被夾到 20），24pt 的尾因 ≥24 規則自動判粗、與 20pt 常規首粗細不同而被擋在組外。放寬粗體閘門讓這種「只因字級而粗」的成員可入組（估值 ≤14% 差仍保護真標題不被併入內文）；組天花板把字級拉到 24 以下後，自動粗體的前提消失 → 跟隨被夾的常規折行首撤粗。
